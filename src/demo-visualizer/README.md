# PneutouchAI HTMLデモ

Created by Kanata the Kid Creator.

実際の恐竜から受け取った圧力とSolistAIの推定結果を、動画・状態画像・波形で表示します。
推定は `src/pneutouch-solist` の実機で行い、HTML/JavaScriptがWeb SerialでUSB UARTを直接読みます。
Pythonは静的ファイルの配信だけを担当します。
Androidタブレットで動かす場合は [`android/README.md`](../../android/README.md) を参照してください。

## 起動

リポジトリ直下で実行します（Python標準ライブラリのみ）。

```powershell
python tools/serve_demo.py
```

1. Chrome / Edgeで <http://localhost:8001/demo-visualizer/> を開きます。
2. 「恐竜につなぐ」を押し、**USB Serial Port (COM7)** を選んで接続します。
3. 恐竜を約1秒押して離します。

動画をウィンドウ全体に表示し、左上に状態画像を重ねます。
波形は最初は非表示です。推定結果を受信すると右下のボタン列の上に5秒間表示し、その後は再び非表示にします。
表示中に次の推定結果を受信した場合は、最新の波形に切り替え、その時点から5秒間表示します。
右下の「⛶ 全画面」を押すと、ステータスと波形も含めてディスプレイ全体に表示します。
Escまたは「全画面を終了」で戻れます。動画は縦横比を保ちながら画面を埋めるため、
画面比率に応じて周辺がトリミングされます。状態画像は4:3の全体を表示します。

現在の配線では、CN9のUSB SerialがCOM6/COM7、圧力受信は **COM7・115200 baud・8N1・フロー制御なし** です。
MCU-LINKのCOM4/COM5とは別です。ほかの計測画面・シリアルモニターはCOM7を切断してください。
LEXIDEのPneutouchAi Write / Debugでは、実機がRun中である必要があります。
ファイルを直接ダブルクリックせず、localhostのURLから開いてください。
既存の計測アプリ（port 8000）と別ポートなので、サーバー同士は共存できます。

## 表示

| 状態 | 画像 | 動画・波形 |
|---|---|---|
| 待機 | `normal.jpg` | `static.mp4`を無限ループ。波形は非表示 |
| 押下検出 | `pressed.jpg`（全体黄色） | 部位の確定を待つ |
| 推定確定 | 部位のJPEG（該当部位が赤） | 部位のMP4を5秒再生し、そのイベントの実測波形を5秒表示 |
| 推定から3秒後 | `normal.jpg` | 動画と波形はそれぞれ5秒まで継続 |
| 推定から5秒後 | 状態画像のタイマーに従う | 波形を非表示にする |
| 動画再生から5秒後 | 状態画像のタイマーに従う | 待機動画を再開 |

現在のモデルは解放後の波形まで使います。黄色はファームウェアの押下検出時、赤は**解放後に推定が確定した時**です。
指が離れた瞬間を外部センサーで検出するものではありません。
次の押下で黄色に切り替わり、次の推定が確定すると前の動画を中断して最新の部位を再生します。
UNKNOWN、無効波形、タイムアウトでは部位の赤表示・新しい部位動画を出しません。
3秒間データが来ない場合や切断時は、状態と波形をリセットします。
音は初期状態でOFFです。画面右下の「音 OFF」でONにできます。

## モード（恐竜／からあげ）

実機の有効スロットの物体（スロット名の先頭 4 文字 `DINO` / `KRAG`）に合わせて表示を切り替えます。
ファームウェアは起動時と再学習のたびに `# PNEM3,…,object=DINO|KRAG` を送り、ビューアーはこの行で
モードを決めます（`object=` がない古いファームウェアや、まだ受信していないときは恐竜モード）。

| | 恐竜モード | からあげモード |
|---|---|---|
| 部位 | TAIL / BACK / LEGS / HEAD | HAT（ぼうし）/ FACE（かお） |
| 状態カード | 状態画像（JPEG） | 画像なし。色の付いたパネルに文字だけ（押下で黄、推定で赤） |
| 動画 | `static.mp4` と部位 4 本 | `krag_static.mp4`・`krag_hat.mp4`・`krag_face.mp4` |
| 表示 | `恐竜とつながっています`・`恐竜モード` | `からあげとつながっています`・`からあげモード` |

物体が変わると、待機動画と反応動画を差し替え（再生中の反応は中断）、押下・推定・波形の表示をリセットし、
`からあげモードに切り替わりました` を出します。同じ物体のスロットに替わったときは、上のバッジの
「スロット n · c 件」だけ更新します。今の物体にない部位の `# PNEC1`（恐竜モードで HAT など）は
「判定できませんでした」として扱います。

## スロットの切り替え

- **実機の SW3**（短押し）: 次の確定済みスロットに切り替わります。`# PNES1,slot=<n>,count=<c>` を受けると
  `スロット n に切り替え中…（学習しています）` を表示し、続く `# PNEM3` で新しいモードに替わります。
  `# PNES1,ERROR,…`（ほかに使えるスロットがないなど）は理由を表示します。
- **ブラウザー**: 接続中はバッジの下に「モデル一覧」ボタンを常に出します（処理中は押せません）。
  接続して最初の圧力データが届くと PST1 でスロット一覧を 1 回自動で読み、「スロット n · 恐竜 · 221件」の
  選択欄を出します（使用中のスロットには「· 使用中」）。ボタンを押すと一覧を読み直します。
  読み出し中・切替中はボタンの下に `スロット一覧を取得中…` / `スロット n に切り替え中…` を出します。
  選べるのは確定済み（state 2）で 4 件以上のスロットです。選ぶと `PAI1 MODE 1` → `PST1 USE` → `PAI1 MODE 0` を送り、
  実機が再学習して `# PNEM3` を送るので、SW3 と同じ経路でモードが替わります。切替に失敗したときは理由を表示します。
  切替後の「使用中」と件数は、一覧を読み直さずに次の `# PNEM3` で更新します。
- 一覧の読み出しと切り替えは、どちらも取得を一度止め（MODE 1）、MODE 0 で再学習します。
  **数秒（2〜4 秒）圧力データが止まります**。この間（最大 15 秒、`# PNEM3` を受けるまで）は
  「圧力データが届いていません」を出さず、受信待ちにもしません。
- コマンドは `本文*<CRC-16/CCITT-FALSE の 16 進 4 桁>` に CRLF を付けて送ります（`src/shared/crc16.mjs`）。
- 一覧を読めなかったとき（PST1 のない古いファームウェア＝`main` のデモ版、またはボードが処理中）は、選択欄を出さず、
  `スロット一覧を取得できませんでした（古いファームウェアか、ボードが処理中です）。「モデル一覧」で再試行できます。`
  を 8 秒表示します（赤字ではありません）。古いファームウェアでは恐竜モードのまま、今までどおり使えます。

## 画像・動画の対応

設定は `assets.json` の `objects.DINO` / `objects.KRAG`（表示名・部位・部位名・画像・動画）。
動画のキーは `static` と大文字の部位名です。読み込み時に、両方の物体に `static` と部位ごとの動画、
恐竜に全画像があるかを確認し、足りなければエラーを表示します。`images: null` は状態画像なしの意味です。
画像は4:3、切り抜きや変形なしで表示します。

恐竜:

| 用途 | 画像（`images/demo/`） | 動画（`videos/demo/`） |
|---|---|---|
| 待機 | `normal.jpg` | `static.mp4` |
| 押下中 | `pressed.jpg` | — |
| HEAD | `head.jpg` | `head.mp4` |
| BACK | `back.jpg` | `back.mp4` |
| LEGS | `legs.jpg` | `legs.mp4` |
| TAIL | `tail.jpg` | `tail.mp4` |

からあげ（状態画像なし）:

| 用途 | 動画（`videos/demo/`） |
|---|---|
| 待機 | `krag_static.mp4` |
| HAT | `krag_hat.mp4` |
| FACE | `krag_face.mp4` |

ユーザー提供のJPEG6枚は1024×768、恐竜のMP4全5本は1660×1244・約5.042秒、からあげのMP4 3本は1920×1080・約3.04秒です。
反応動画は5秒で待機に戻します。差し替え動画が5秒未満なら終端で戻ります。
`pushing.jpg` は `pressed.jpg` に改名しました。

## 波形と通信

- `PNEU1`: 実測ADC生値。受信順序を検査し、最大800サンプルを保持。
- `PNEE1 START`: 全体黄色。IDで後続の推定と対応付け。
- `PNEC1`: 実機のHEAD/BACK/LEGS/TAIL（からあげはHAT/FACE）に従って表示。ブラウザー内で再分類しません。
  今の物体にない部位とUNKNOWNは「判定できませんでした」。
- `PNEF1`: 推定直後に届くイベント開始・終了時刻を使って表示区間を確定。
- `PNEM3,…,slot=<n>,count=<c>,…,object=DINO|KRAG,…`: 起動時と再学習のたびに届く。モードとスロット表示を決める。
- `PNES1,slot=<n>,count=<c>` / `PNES1,ERROR,<理由>`: 実機SW3のスロット切替。
- `PAI1,MODE,0|1`: MODE 1 は取得停止なので、表示をリセットする。`PST1,…` / `PAI1,ERROR,…` はスロット一覧・切替の返信。

グラフは検出前約0.85秒から波形取得完了後約0.35秒までです。
縦軸は直前の基準値（検出前0.825〜0.325秒の中央値）を引いたADC counts、横軸は圧力による押下検出からの秒数です。
波形の平滑化や時間伸縮は行いません。基準区間を受信していなければ生値表示とし、一部のみの記録と明記します。
「波形取得完了」の線は指の解放時刻ではありません。現在のHEAD/LEGSの混同はモデルの制限として残ります。

node --test tests/demo.test.mjs tests/demo-store.test.mjs tests/demo-slots-ui.test.mjs tests/crc16.test.mjs tests/protocol.test.mjs tests/serial.test.mjs

全JPEG/MP4の読込、実記録のUART再生、4部位の対応、3秒/5秒の独立した切替、
待機ループ、切断、スマートフォン幅の表示を確認しました。
全面動画と左上の状態画像、右下の波形配置、推定時だけの5秒表示、パネルを含む全画面への移行・解除も確認済みです。
試験用のUART入力は隔離したテストブラウザーだけに注入します。本番ページに自動再生データや疑似推定は含めません。
ブラウザー統合試験は配線や新しい実押下の評価を代替するものではありません。
