## M1: Phase 0 — 圧力をPCへ送る

実装は作成済み。起動と実機確認は[Phase 0の手順](phase0-bringup.md)を使う。
Cの取得・安定待ち、PCの解析・記録・接続解除、疑似シリアル通信をテストし、
旧プロジェクトの9件に加え、新プロジェクトの計測・起動ソース10件をArm向けにコンパイルした。
Windows Debugの最終リンク・HEX生成、PneutouchAi Writeでの書き込み、COM7での実測を確認。
直近30秒で1190点、実効39.72 SPS、欠番0。ユーザーが繰り返し押している間に生値が大きく変化した。

実装内容:

1. `src/pneutouch-solist/` の動作確認済みPneutouchAiをメインにし、`S_PneuTouch` へ取得処理を移植。
2. 元プロジェクトのROHMコードとLEXIDE環境を使い、`config.py`から取得設定を生成する。
   [追加資料の移植メモ](reference-integration.md)に従い、RB用設定とDT用設定を分ける。
3. 電源保持、外部リセット解除、48 MHz PLL、WDT、時刻、UARTを初期化する。
4. HX710Bの非ブロッキング準備待ち、24ビット読取、27パルス、符号拡張を実装。
5. 初期安定待ち、未接続時のタイムアウト、復帰時の安定待ちを扱う。
6. MCU時刻・連番付きの生値を115200 baudで送る。
7. `learning-tool`に接続・波形・CSV保存、CLI受信を実装する。

検証:

- Cホストテスト: 正負の境界、MSB順、25/27パルス、未準備、26パルスの誤使用防止。
- PCテスト: 行の分割・連結、破損行、長過ぎる行、欠番、再起動、CSVの上書き防止。
- LEXIDEで最終リンク・HEX生成。設定したMCUとメモリー使用量を確認する。
- 電圧確認後に配線し、書き込み・Run・UART接続を実施する。
- 実測で概ね40 SPS、圧力でrawが変化、解放で戻ることを確認する。
- SCK Highが50 µs以下であること、未接続で正常値を偽装しないことを確認する。

**完了条件**: 実機の圧力変化をPCで表示し、再解析できるCSVを保存できる。
ホストテストやコンパイル成功だけで完了としない。

## M2: 気密と7区画の生波形（原案Phase 1～4）

2026-09-20の予備試験は各部位5～8回、完全43回。立ち上がり、負側幅、正負面積比に差がある。
各部位1記録のため独立評価は未成立。まず「約1秒で握って離す」条件で部位を混ぜて追加収集する。
接触開始は圧力から自動検出する。評価用の同期接触時刻を、デモ動作の必要入力にはしない。
詳細・生CSV・再現コードは[実測分析](pressure-validation-20260920.md)に保存。

1. 恐竜の各部位からセンサーまで圧力変化が届くか、経路順と穴の閉塞を確認する。
2. 押した状態を保持し、漏れとTPUの緩和挙動を調べる。
   保持中の圧力低下だけで漏れと断定せず、チューブ単体等の比較も行う。
3. チューブの長さ・内径、接続、造形条件を固定して記録する。
4. 各Zone最低30回、計210接触イベントを収集する。可能なら各50回。
5. 同一部位の重ね合わせ、部位間比較、生値・ベースライン補正・正規化を比較する。

押し方はまず1人・同じ指・同程度の強さと速度へ揃える。
試行間に基準圧力へ戻る時間を取る。接触前も記録する。
区画を順番に全部収集するだけでなく、測定ドリフトの影響を調べるため順序を変えた試行も入れる。

**進む条件**: 部位差が繰り返し観測でき、漏れ・飽和・欠測を説明できる。
区別できない場合は、構造・配管・取得系を修正する。

### サンプル速度の判断

HX710Bは公称10/40 SPS。SCKだけを高速化しても40 SPS超の変換設定にはならない。
25 msより短い変化や少数点にしか現れない差が重要なら、このADCでは不十分な可能性がある。

まず40 SPSで測る。差が観測できないときは、構造に差がないのか、取得系が遅いのかを切り分ける。
高速ADCへの変更はその判断候補とし、200 SPS等をこのモジュールのソフト変更だけで約束しない。
ADC変更時はブリッジ増幅、入力範囲、基準電圧、ノイズ、インターフェース、電源も再設計する。
低コストの比較候補はMPS20N0040Dを再利用したHX711の80 SPS。
変更の採用は未決定で、[つなぎ替え条件](sensor-options.md)を満たした基板で比較する。
さらに速い変化の調査には、差動増幅回路＋[DT内蔵ADC](mcu-adc-option.md)も候補にする。
HX711を必須の中間段階とせず、必要帯域とノイズ・回路工数で選ぶ。

## M3: イベントと学習入力（原案Phase 5～6）

- リングバッファ、非接触時のベースライン、開始閾値・終了条件・不応期を実装。
- 接触前のプリトリガーと接触後データから固定長窓を作る。
- 128点を確定値にしない。40 SPSでは約3.2秒分なので32/64/128点と判定遅延を比較する。
- ベースライン補正を第一候補とし、正規化・差分波形の効果を比較する。
- Solistpanの参考資料を踏まえ、立ち上がり時間・ピーク・面積・減衰などの少数特徴量と
  波形入力を比較候補にする。FFTは周波数帯ごとの違いが有効かを確認してから採用する。
- 24ビット生値をそのままint16へ切り詰めない。
  Solist-AIへ渡すスケール、クリップ範囲、bfloat16変換を明示する。
- ラベルはサンプル数ではなく、接触イベント単位で管理する。

**完了条件**: PCで正解ラベル・試行・窓位置を確認でき、同じ前処理を再現できる。
ノイズだけのイベント、連続押し、保持、離す動作をどう扱うか説明できる。

## M4: Solist-AIの分類方式を確立（原案Phase 7の前提）

配布デモは入力の再構成誤差による異常検知であり、そのまま7分類にはならない。
追加された公式`SupervisedLearning`とUARTの4分類例を土台に、
[AI実装メモ](solist-ai-implementation.md)の1モデル4/7出力構成をDTへ移植する。
新SDK一式を第一候補にし、旧ヘッダー・ライブラリーと混ぜない。

1. 小さい入力と教師データで学習→推論→結果取得の最小例を作る。
   配布PythonのFFT学習・seed復元・リセットフレームとReleaseリンク設定を修正し、モックで検証する。
2. 1モデルの出力4/7要素に教師ベクトルを与える方式を第一候補として検証する。
3. ライブラリーの対応サイズ、重み領域、通常RAM/AI領域、実行時間を確認する。
4. 最大スコア、次点との差、未知・非接触の扱いを決める。
5. Beta/P、モデル設定、前処理、SDK版を保存し、再起動後の推論一致と追加学習を検証する。
6. 公式UARTの8E1バイナリーとPhase 0の8N1/PNEU1を区別し、双方向通信の仕様を確定する。

配布設定の`ODL_MAX_INST_NUM=2`はモデルインスタンス数であり、クラス数ではない。
7区画だから7モデル必要と決めつけず、逆にマクロだけ増やして対応できるとも考えない。

**完了条件**: 分類に使えるAPI構成とメモリー・時間上の制約を実機で確認する。
生スコアは確率として表示しない。

### 直接分類の後に検討する改善

[Solistpan調査](research-notes.md)の分類・知識蒸留を参考にするが、
まず正解ラベルを使う4/7クラス分類を基準にする。60位置への分割は初期要件にしない。
MCUモデルの精度不足が残る場合、同じ取得波形からPCモデルがより良く分類できるかを比較する。
差が出た場合にのみ、PC教師の出力を教師信号へ混ぜる蒸留を候補にする。
元資料の75%/25%や隠れ層32を、そのまま必須設定として採用しない。
これは後続の比較実験であり、Phase 0へ教師モデルの実装や依存ライブラリーを追加しない。

## M5: 4グループ → 7区画（原案Phase 7～12）

- まず首・頭／背中／足／尻尾で、取得からMCU推論・PC表示まで通す。
- 次に7区画へ拡張する。区別できない区画は混同行列で明らかにする。
- 学習に使わなかった新しい試行を各Zone約20回、計140回取得して評価する。
- 同一イベントの窓や隣接サンプルを学習・評価へ分散させない。試行・セッション単位で分割する。
- 強さ、速度、操作者を段階的に変え、精度と誤反応・遅延を記録する。
- ハイパーパラメーター選択に使った検証データと、最後の評価用データを区別する。

**完了条件**: 未学習データの結果と、できること・苦手なことを数値で説明できる。
精度の合格値はM2の実測を踏まえて確定する。架空の目標達成値を置かない。

## M7: 構造の改善（原案Phase 13～15）

オリフィス径、非均一な穴、チャンバー容量、流路長、接続順を一度に全部変えず、
比較可能な単位で変更する。STLの版とデータセットを対応付ける。
構造変更後は気密・波形・学習・評価を再実施し、古いモデルをそのまま流用しない。
Solistpanの非対称固定の考え方に対応して、空気圧経路の非対称性が位置ごとの違いを
増やすかも比較する。現在の穴径・接続順を基準に、区別できない部位から検討する。
