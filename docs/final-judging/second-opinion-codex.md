# 第二意見（Codex）と、それへの判断

2026-10-14。Fable の判断（[strategy-review.md](strategy-review.md)）とは独立に、Codex にリポジトリを読ませて同じ問いに答えさせた記録。
要約は Codex の報告、「判断」は Fable。

## Codex の主張（要約）

1. **GPT案の誤り**: 特徴抽出のMCU移植は完了済み。分割評価も存在するが独立テストではない。「振幅に依存しない12特徴だけ」は現行2段モデルには当てはまらない（専用モデルは正圧ピークを使う）。登録済みデモ動画はUARTと同期しておらず証拠にならない。
2. **最も効果が高い変更は、収録方法を変えて未使用セッションで実証すること**。部位別の連続収録をやめ、強弱・4本の足・部位順を混ぜた複数セッションで取り、モデル固定後に保留セッションで評価する。無反応（INVALID）を含む全操作の成功率、混同行列、表示遅延、同条件の無編集実演を出す。**teach モードは、この実証が成立した後の追加点**。
3. **teach モードの実現性は高いが、精度改善は未保証**。3〜5人日＋実機検証2日。注意点: 正規化固定、専用モデル用の peak も保存、FRAM 書込は `void` なので読み戻し確認、学習中は取得を止めて検出器を再初期化、`PAI1` 復帰時に固定モデルへ戻る処理の修正、生成器の `uint8_t` 順序と255件上限。
4. **からあげ氏が突く点**: 最近重心法 22/22・19/22 に対し Solist-AI 21/22・19/22 で精度優位はない。一般化の証拠がない。多数派 LEGS だけで 63.6%。「本当にチップで判定しているか」は答えられる（推論に教師ゼロ、`pressure_model.c:106`）。未知操作の拒否・確率校正は未実装。
5. **GPT案の見落とし**: LEGS 候補 26 件中 9 件が振幅不足で棄却されており、採用済みイベントだけの正解率では体験品質を表せない。検出から特徴確定まで中央値 1.385 秒で、「推論 5ms」を体感遅延として宣伝できない。構造が位置を符号化している証明は未完了。demo-visualizer の `notice()` は `error=false` の文言を表示しないため、INVALID 時の再操作案内が画面に出ない（`src/demo-visualizer/app.mjs:12,55,57`。確認済み）。

## 判断

**同意する点**（計画に取り込んだ）:

- 独立評価が最初。[plan-10days.md](plan-10days.md) では 10/15 に収録、10/16 に teach の go/no-go という順にしてある。収録は部位を混ぜ、INVALID / TIMEOUT を数え、足4本のラベルも残す（将来の7分類に使える。コストはゼロ）。
- 遅延の言い方。発表では「指を離してから約1秒半で結果」と言う。5ms は「マイコン内の推論時間」としてだけ使う。
- 検出率を出す。弱い押しが棄却される現象は、審査員が触れない以上は自分で数字にして見せるしかない。
- `notice()` の修正。1行の変更で、デモ中に「もう一度押して」が出るようになる。10/20 の作業に入れる。
- teach モード実装の注意点はすべて [teach-mode-spec.md](teach-mode-spec.md) に反映（読み戻し確認、学習中の取得停止、`PAI1` 復帰時の FRAM 再読込、peak の保存）。

**同意しない点**:

- 「teach モードは実証の後の追加点」という優先順位。独立評価は必要条件だが、それだけでは**完成度の弱さを数字にしただけ**で終わる。最優秀賞に届くには、その弱さ（操作者差、押し方差）に対する答えが要る。今の構造と10日間で答えになり得るのは teach モードだけで、しかも Solist-AI 活用度の評価に直結する。だから両方を S にし、10/16 の検証で効果がなければ「ゼロから教える」デモに切り替える、という形で賭け金を限定している。
- 「収録方法を変えてモデルを作り直す」は、既存60件の学習データと混ぜる設計変更になり、正規化の再計算と埋め込みデータの再生成が必要。10日で両方（再収録＋再学習＋teach）はできない。**埋め込みモデルは `demo-v1` のまま固定し、新しい収録は評価と teach の材料に使う**。
