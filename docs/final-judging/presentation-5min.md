# 5分プレゼンの構成と想定質疑

ルール: 5分厳守、作品の特徴・Solist-AI の活用方法・プロトタイプの動作が伝わること、質疑3〜4分（[イベントページ記録](final-judging-event.md)）。
画面共有は自分で行う。スライド共有と手元カメラ（恐竜＋LCD）の切り替えを事前に練習する。

## 想定質疑（根拠付き）

**Q. なぜ1個のセンサーで場所が分かる？**
7つの部屋が穴1個ずつで直列につながっていて、押した部屋の空気が穴を通って尻尾のセンサーに届く。押す場所で山と谷の形（立ち上がり、減衰、面積の比）が変わる。ただし今の構造では頭と足の形が近く、そこが課題。

**Q. 単純な閾値でよくない？（からあげ氏）**
圧力の大きさだけでは無理。頭と足の山の高さは記録によって大小が逆転した（HEAD 201 < LEGS 271 → HEAD 247 > LEGS 125 千counts）。だから大きさを使わず時間と比の12特徴量にしている。

**Q. 12特徴量なら k-NN でも当たるのでは？ Solist-AI の必然性は？**
はい、PC の最近重心法でも同程度に当たる。Solist-AI を使う理由は精度ではなく、**16KB のマイコン上で、押すたびに逐次学習できること**。だから「教える」ができ、持ち主の押し方に合わせて賢くなる。PC の k-NN はこの恐竜の中に入らないし、その場で学ばない。

**Q. 学習データは何件？ 評価は？**
応募時: 1日1人の60件を起動時に学習。評価は同じ記録内の分割で 21/22、保留8件で 6/8。それでは独立評価と言えないので、10月に別の日・2人で各部位10回以上を取り直した（→混同行列）。

**Q. 押す強さや人が変わったら？**
変わると当たりにくくなる。特に頭と足。そのための「教える」モード。起動時の学習に加えて、使う人が数回教えると適応する。

**Q. 7か所全部分かる？**
設計は7部屋。今は4分類。足4本は波形が近く、オフラインで7部位 79%、誤りはほぼ足同士。足を分けるには頭側と同じく流路の設計変更が要る。

**Q. 既存の空気圧触覚センサーと何が違う？（AirTouch を知っていますか？）**
知っている。AirTouch（CHI 2020）はポンプで空気を送った硬い3Dプリント物体の穴を指で塞いで、気圧センサー1個で12か所を当てる。PneuTouch はポンプなしの受動式で、柔らかい物体をどこでも押せて、学習がチップの中で完結する。流路の動特性を情報源にする考え方は Pneumatic Reservoir Computing（2021）に近い。世界初とは言わないが、この組み合わせは見つけていない。

**Q. PC は要らない？**
学習・推論・LCD表示・教える操作はボードだけ。PC は画面の恐竜の動画を出すためだけ。

**Q. 反応は速い？**
指を離してから約1.5秒。押している間の波形と、離したあとの谷まで見てから判定するため。マイコン内の推論は5msだが、それを体感速度とは言わない。弱すぎる押しは「読めなかった」と表示してもう一度を促す。

**Q. 同時に2か所押したら？ 長押しは？**
今は未対応。1秒押して離す操作が前提で、4秒で打ち切る。連続押し・同時押しは次の課題。

**Q. 実用化は？**
ぬいぐるみ、ソフトロボットの外装、介護用クッションなど「センサーを並べにくい柔らかい物」。気密の経年変化、温度、個体差の検証が必要。

**Q. 何が一番大変だった？（西村氏・栗原氏向け）**
頭と足が同じ形に見えること。空気の回路は思ったより素直で、遠いから遅いという単純な話ではなかった。だから「教える」を作った、という流れで答える。
