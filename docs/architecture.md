# ディレクトリ構成と責務

## 採用する構成

以下は**実装時の配置計画**。この整理コミットではドキュメントを先に確定し、
アプリ本体・IDE設定・準備スクリプトは次の実装で追加する。

```text
pneutouch-ai-rehc2026/
├── README.md
├── config.py                          # 設定の原本（実装時に追加）
├── docs/                              # コンセプト・設計・手順・調査
├── 3d-models/
│   └── dino-air-7segments.stl
├── src/
│   ├── pneutouch-solist-ai/            # LEXIDE-Ωプロジェクト
│   │   ├── .project / .cproject
│   │   ├── .settings/
│   │   ├── Source/                    # 自作のCソース
│   │   ├── generated/                 # 設定ヘッダー・リンカー設定（Git除外）
│   │   └── vendor/                    # ROHM/CMSISをローカル展開（Git除外）
│   ├── learning-tool/                 # 開発者向け波形・データ収集・学習制御
│   │   └── capture.py                 # CLI受信。画面と独立して動作確認できる
│   ├── demo-visualizer/               # 来場者向け恐竜・動画・波形
│   │   └── media/                     # ユーザー提供動画
│   └── shared/                        # PC側で共有する通信解析・部位定義等
├── tools/                             # 依存資料展開、テスト、ローカル起動
├── tests/                             # Cホスト・PC通信処理等のテスト
├── captures/                          # 実測CSVとメタデータ（Git除外予定）
├── build/                             # ビルド・一時出力（Git除外予定）
└── references/                        # 配布資料・参考コード（Git除外済み）
```

波形の比較・学習データ収集は`learning-tool`へ統合するため、
初期段階では別の`src/visualiser/`を作らない。
発表用の`demo-visualizer`は、動画や大きな恐竜図が主役なので独立させる。

## MCU: pneutouch-solist-ai

LEXIDEでフォルダーを選んで取り込めるプロジェクトにする。
コピー元の参考デモをそのまま編集するのではなく、必要な起動・周辺回路のコードを利用して、
PneuTouch用のアプリを組み立てる。

段階的なモジュール分割:

| 担当 | Phase 0 | 後続 |
|---|---|---|
| ボード制御 | PLL、WDT、電源保持、GPIO、UART、時刻 | FeRAM、学習モデル保存 |
| センサー取得 | HX710B読取、レート選択、符号拡張、タイムアウト | センサー変更時の差し替え |
| データ処理 | 生値の送信 | リングバッファ、イベント、前処理 |
| AI | まだ組み込まない | Solist-AI学習・推論・判定保留 |
| 通信 | サンプル・状態の送信 | 学習指示の受信、ACK、推論イベント |

HX710Bのビット処理とGPIO操作を分け、前者をMacでテストできるようにする。
通信やAIでSCK Highを長時間維持しない。取得処理の時間制約を独立させる。

## PC: learning-tool

Phase 0では、シリアル接続、生値、波形、CSV保存、手動Zoneラベル、受信エラー表示まで。
CLIも用意し、ブラウザ非対応やUSB接続の切り分けに使う。

後続ではイベント単位の記録、波形重ね合わせ、ベースライン補正・正規化表示、
学習指示、試行数、混同行列、モデル・構造・前処理のバージョン管理を追加する。
**learning-toolという名称でも、初期版でSolist-AIの学習ができるとは限らない。**
提供機能はフェーズごとに画面とREADMEへ明記する。

## PC: demo-visualizer

恐竜図の部位強調、リアクション動画、実測波形を同時表示する。
動画はユーザーが用意し、Zone IDに対応付ける。初期確認はローカルファイル選択、
常設時は`media/`と設定ファイルの対応表を使う方針。公開が必要な場合は素材の扱いを確認する。

入力を「センサー生値」「推論イベント」「手動プレビュー」に分ける。
手動プレビューはAI未接続でも動画・画面を検証するための機能。
推論イベントの代わりとして隠れて使わない。
7クラスが成立する前に4グループを使う場合、`class_id`と物理`zone_id`を分離する。

## 共有する通信と部位定義

Web Serial APIを使うPC画面では、行分割、フレーム検証、欠番・再起動検出、
Zone名と色の対応、接続エラー処理を共通化する。
同じシリアルポートを2画面・CLIで同時に開かない。初期は利用するアプリを切り替える。
必要になった段階で1接続から複数画面へ配信する仕組みを検討する。

### Phase 0の採用プロトコル

ASCII、CRLF終端、115200 baud、8N1、フロー制御なし。

```text
# PneuTouch Phase0; PNEU1,seq,ms,raw; nominal_sps=40
PNEU1,0,625,-12345
PNEU1,1,650,-12201
# ERROR,HX710B_TIMEOUT
```

例示値であり実測値ではない。

| フィールド | 定義 |
|---|---|
| `PNEU1` | フレーム種別・バージョン |
| `seq` | uint32のサンプル番号、MCU再起動で0へ戻る |
| `ms` | MCU起動後のミリ秒、uint32で周回する |
| `raw` | 符号付き24ビットADC値を10進数で表す |
| `# ...` | 状態・エラー。測定サンプルとして扱わない |

PC受信が分割されても行を復元する。欠番・不正行を通知し、欠けた値を0で補わない。
チェックサムは初期形式に含めないため、合法な数値への化けを完全には検出できない。
長期収集へ進む際にCRC、再同期、プロトコル互換性を評価する。
配布デモの独自通信・高速転送と、この新しいプロトコルの互換性は持たせない。
追加のROHM UARTサンプルも115200/8E1のバイナリー要求応答で、PNEU1とは別仕様。
M4の検証時に通信モードを明示し、[移植メモ](reference-integration.md)に沿って双方向化を設計する。

### 記録するデータ

Phase 0: `host_utc, seq, mcu_ms, raw, label`を基本とする。
ラベルは物理Zone 1～7、非接触は0。未指定は空欄として、非接触と混同しない。
ブラウザのラベル切替時刻とMCU取得時刻にはUSBバッファ分のずれがあり得るため、
学習用イベントでは開始・終了・試行番号を別管理してラベルを確認する。

後続では`session_id`, `trial_id`, `event_id`, 操作者、押し方、モデル・構造・チューブ条件、
実測サンプル周期、前処理設定を記録する。生値は常に残し、前処理済みデータと区別する。
128点などの窓長はセンサーの実測レートに合わせて決める。

### 後続の通信設計項目

学習モード、対象クラス、取得開始/停止、学習/推論開始、モデル保存/読込、
推論結果、スコア、判定保留、イベントIDの形式はAI APIの検証後に確定する。
コマンドID・応答・タイムアウトを定義し、失敗を画面へ返す。
モデルの生出力を校正済みの確率として「92%」などと表示しない。

## 設定と依存物

ランタイム設定はルートの`config.py`へ集約し、CヘッダーやPC向け設定へ展開する方針。
クロック/baud、取得レート、タイムアウト、窓長、録画上限、動画対応表をばらばらに持たない。
ボード固有レジスター設定は資料の根拠と一緒にC側へ置く。

自作コード・IDEメタデータ・展開手順をGit管理する。
配布コードは元の著作権表示を保ってローカル展開し、`references/`と展開先をGit除外する。
生成物・測定データ・動画をどこまで共有するかは用途と容量に応じて決める。
