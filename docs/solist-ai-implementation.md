# Solist-AIの分類・前処理・モデル保存

調査日: 2026-09-20。[追加資料一覧](reference-catalog.md)のN番号とパス略号を使う。
以下は配布資料・ソースの確認結果と実装方針。DT実機での動作・分類精度は未検証。

追記: 同日の後続作業で[保存CSVによる実機学習・4分類比較](solist-chip-validation-20260920.md)を完了した。
本書の調査時点の記述と区別する。実機ではPneutouchAi同梱の旧ヘッダーVer 1.2.0と
`SolistAi_Library_2_256_64.a` を使用し、下表の新SDKへはまだ移行していない。

## 結論と採用候補

**公式の教師あり学習・4分類サンプルが存在する。**
PneuTouchは「異常度を7段階に分ける」のではなく、1モデルの4/7出力へ部位の教師ベクトルを与える。
初期候補は32/64/128点の圧力窓または少数特徴量、隠れ層32/64、出力4→7。
これは比較実験の候補で、性能や実機での利用可能サイズを保証する設定ではない。

| 根拠 | 確認内容 | 活用方法 |
|---|---|---|
| N1 PDF p.32–33、`REF/samples/Solist-AI/SupervisedLearning/src/MlTask.c` | 20入力・40隠れ・20出力、45学習例・4テスト例。入力と教師を別配列で渡す | C側の学習・推論・待機・結果取得の最小例 |
| N5 PDF p.7–8、`UART/samples/Solist-AI/SolistAI_UART_IF/script/SolistAI_Classification.py` | 520入力・66隠れ・4出力、4エポック、MCUで学習・推論 | PCからラベル付き入力を送り、MCU分類を検証する構成 |
| N11 PDF p.28–36 | 4種類をone-hot教師で学習し、未学習データの出力を評価する説明 | 7区画へ拡張する際の教師ベクトルと評価の根拠 |

`SupervisedLearning`は演算結果を期待値と照合する例で、恐竜の分類器ではない。
Python例は出力・lossをグラフ化するが、混同行列・部位別精度の評価はPneuTouch側で追加する。
例の正規化`(x - 220) / 300`、520入力、4エポック、`l2param=0.1`は付属データ向けである。
`ACTIVATION`等の定数には呼出しへ渡していないものもあるので、定数名だけで有効設定を判断しない。

## 入出力数とクラス数

モデルインスタンス数は分類クラス数ではない。7区画ならまず1モデル・7出力を試す。
以前の「入力256・隠れ64・2モデル」は旧配布ライブラリーの構成であり、MCU全体の固定上限ではない。

N3 PDF p.17には、モデル数1・入出力512・隠れ64や、モデル数1・入出力4000・隠れ10など、
メモリー量に応じた組合せの目安がある。これを各項目独立の最大値とは解釈しない。
公式4分類例の520→66→4も、圧力データでの動作確認とは別である。

資料間の不一致もあるため、境界サイズを推測で採用しない。

| 項目 | 確認した不一致 | 判断 |
|---|---|---|
| 1モデル・隠れ128の入出力数 | N3 PDF p.17は160、N6 PDF p.12は192 | 表を画像でも確認。`ODL_Initialize`の成否と実測を優先 |
| FFTの最大入力 | N3 PDF p.31の概要は2048、同ページAPI説明は1024。N7の`fft.h`は2048 | 初期32/64/128点なら両記載の範囲内。最大長は別途検証 |
| 一部ハイパーパラメーターの範囲 | N3とN6で忘却係数・正則化等の記載が異なる | 採用SDKのソース・返却値と照合し、資料の範囲を合成しない |

## 学習・推論の処理順

新SDKのAPI宣言は`UART/driver/inc/mlacc_odl.h`、動作説明はN3 PDF p.18–19。

1. DT固有の起動と、AI周辺機能・割り込み・WDTを整える。ボード移植後に最小例を確認する。
2. モデル数、入力長、隠れ層数、出力長、各パラメーターを設定する。
   複数モデルを使う場合はインスタンス番号の小さい順に`ODL_Initialize`を呼ぶ。
3. 新規学習は`ODL_Reset`、既存モデルの再開は設定整合を確認してBeta/Pを復元する。
   復元後に`ODL_Reset`を呼んで重みを消さない。
4. 圧力窓を前処理してbfloat16へ変換し、Zone教師と`ODL_StartTrain(model, x, t)`へ渡す。
5. `ODL_IsBusy`で完了を確認する。待ち時間を制限し、WDT・取得処理を維持する。
6. 推論は`ODL_StartPredict`→完了待ち→`ODL_GetResult`。
   正解がある検証時だけ教師を使ってlossを取得する。
7. 出力の最大値と次点差を評価し、部位または判定保留を返す。

`ODL_StartTrain`自体は出力・lossを計算しない。学習直後に古いlossを表示しない。
学習前/後のlossを表示するなら、どの重みによる推論結果かを明示して別途推論する。
教師あり推論で正解ラベルが不要なことと、lossの評価に正解が必要なことを区別する。

**教師ベクトルの提案:** 7分類ではZone 1なら`[1,0,0,0,0,0,0]`、Zone 7なら末尾だけ1。
4グループ版は別のクラス対応表を持つ。0=非接触という記録ラベルを、そのまま7出力へ混ぜない。
初期はイベント検出と判定保留で非接触を扱い、8クラス化は必要性を確認してから判断する。

## アルゴリズム上の注意

N11 PDF p.5、p.30–36とN3 PDF p.18、p.34–36から確認:

- Alphaは乱数等で設定する入力→隠れ層の重み。逐次学習ではBetaを更新し、追加学習用にPを保持する。
- `activationFunction`は**隠れ層**の関数。`SIGMOID`はhard sigmoidで、softmax出力ではない。
- MAE/MSEの選択はlossの計算方法。資料は「学習には影響しない」としている。
  一般的な誤差逆伝播モデルの損失関数選択と同一視しない。
- 出力は0未満や1超になる場合がある。N11の例にもその値があり、未校正スコアを確率表示しない。
- `scaleGamma=0`は通常の3層構成。ESNは状態のリセット・持越しも必要なので後続の比較候補に留める。

Solistpan資料の固定Alphaという説明は公式資料とも整合する。
ただし隠れ層32はMCU全体の上限ではなく、Solistpan固有条件の詳細は引き続き未確認。

## 24ビット圧力値とFFT

`ODL_ToBfloat16`はint16の固定小数点入力を変換するAPI。
HX710Bの符号付き24ビット値はint32で保存し、baseline補正→スケール→クリップ→変換を定義する。
学習と推論で同じ設定を使い、端数処理・負値・飽和境界をテストする。
bfloat16は16ビット整数ともIEEE binary16とも異なる。型が`int16_t`でも通常のキャストでは変換できない。

FFTを採用する場合の根拠と確認項目:

- N3 PDF p.31: 出力は`abs(real) + abs(imag)`。一般的な`abs(rfft(x))`やパワースペクトルと同じではない。
- N点入力に対しAPI上はN/2+1点、先頭はDC。窓関数はnone/Hannを揃える。
- `REF/samples/Solist-AI/FftSample/src/data/`に64入力・33出力の期待値があり、移植時の照合に使える。
- `ANOM/samples/Solist-AI/AnomalyDetectionDemo/src/Preprocess.c`はN/2個を取得している。
  APIの出力長とデモが採用する特徴数を混同せず、残すbin・DC除去・正規化を仕様化する。
- PCで作る特徴とMCUのFFT結果を同じ入力で比較する。FFT処理を速くしてもHX710Bの40 SPSは増えない。

M3ではまず生波形と少数特徴量を比較する。加速度用FFTの有用性だけから、圧力でも必須とは判断しない。

## モデル保存とメモリー

N3 PDF p.35の式では、隠れ層M・出力Nの重み関連メモリーは次の通り。
以下の数値は式による概算であり、通常RAMのバッファ・スタックやアプリ全体の容量ではない。

| 用途 | 資料の式（byte） | M=32、N=7 | M=64、N=7 |
|---|---|---:|---:|
| 学習・推論時の重み等 | `(N + 2*M)*M*2 + 16*1024` | 20,928 | 33,664 |
| 追加学習を再開する保存データ | `(N + M)*M*2` | 2,496 | 9,088 |
| 推論専用の重み保存 | `N*M*2` | 448 | 896 |

通常ワークRAM16 KBと、AIが使う領域を分けて設計する。
この表だけで入出力バッファを含めたモデルの収容可否は決められない。
最終リンクのmap、SDKの初期化結果、実機動作をセットで確認する。

保存対象の提案:

- Beta、および追加学習する場合のP。
- 入出力数・隠れ層数・活性化・seed・scaleAlpha/Gamma・leakRate・忘却係数・正則化等。
- 前処理版、取得レート、窓長、スケール、クラス対応、STL/配管版、SDK識別子。
- 形式版、長さ、CRC等の破損検出情報。保存中断や異なる構造のモデルは適用しない。

`REF/driver/src/ai_ram_save.c`は**プログラムFlash**へ4 byteずつ書き、2 KB境界でセクター消去する。
DTのFeRAM保存ドライバーではない。予約領域を持たずに使うとコードと重なるため直接流用しない。
PneuTouchではDTのFeRAMを第一候補に、電源再投入後の推論一致と追加学習の継続を検証する。
Python例の保存形式は新パラメーターすべてを含まないため、完全な再現用形式としては不足する。

## M4/M5で残す検証記録

| 検証 | 成功の判断 |
|---|---|
| 小さな教師あり例 | 入力・教師・予測が追跡でき、初期化失敗や待機タイムアウトを検出する |
| 4→7出力 | 別試行・別セッションの混同行列、誤反応、押下から判定までの遅延を記録 |
| 前処理一致 | 同じ生値からPC/MCUの入力ベクトルを比較。許容誤差を定義 |
| 保存復元 | 電源再投入前後の出力一致、破損/版違いの拒否、P復元後の追加学習を確認 |
